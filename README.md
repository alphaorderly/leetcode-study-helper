# 리트코드 스터디 도우미

DaleStudy `leetcode-study` 형태의 워크스페이스에서 내 풀이만 빠르게 찾고, 아직 풀지 않은 문제의 빈 제출 파일을 만드는 VS Code 확장입니다.

## 주요 기능

- `problem-categories.json`과 문제 폴더를 이용한 저장소 자동 감지
- 멀티 루트 워크스페이스 지원
- 닉네임 기준 풀이 유무 표시
- 풀이 파일명과 upstream 원격 저장소의 푸시 여부 표시
- 4기 문제 목록을 주차별 또는 난이도별로 분류
- 문제명·주차·난이도 검색과 풀이 상태 필터
- 현재 표시 파일을 기준으로 미푸시 풀이만 필터
- 내 풀이 파일을 보고 있을 때 LeetCode 문제 본문을 사이드바에서 바로 확인
- 현재 Python 편집 내용에서 여러 `Solution` 구현을 골라 로컬 테스트 실행
- 문제명을 폴더 슬러그 대신 읽기 쉬운 제목으로 표시
- 각 문제 카드에서 LeetCode 문제 페이지 바로 열기
- 풀이가 있는 문제 카드를 클릭해 에디터에서 바로 열기
- 풀이가 없는 문제 카드를 클릭해 `<닉네임>.<선택 언어 확장자>` 빈 파일 생성
- 두 번의 확인을 거쳐 내 풀이 파일을 휴지통으로 이동
- 버튼 한 번으로 내 제출 파일의 끝 줄바꿈을 라인린트 규칙에 맞게 일괄 수정
- 파일 생성·삭제 및 문제 목록 변경 자동 반영
- Git 커밋·체크아웃·푸시 상태 변경 자동 반영

닉네임은 파일명의 첫 번째 점 앞 부분과 **대소문자까지 정확히** 비교합니다. 예를 들어 닉네임이 `CaseUser`이면 `CaseUser.py`와 `CaseUser.go.md`는 표시되지만 `caseuser.ts`는 표시되지 않습니다.

## 사용법

1. `problem-categories.json`과 문제 폴더가 있는 저장소를 VS Code로 엽니다.
2. 활동 표시줄에서 **리트코드 스터디 도우미** 아이콘을 선택합니다.
3. 상단에서 닉네임과 기본 언어를 입력하고 **적용**을 누릅니다.
4. 풀이가 있는 문제 카드를 누르면 풀이가 열립니다.
5. 풀이 파일을 연 상태에서 **현재 문제 보기**를 누르면 문제 설명, 예제와 제약조건을 사이드바에서 확인할 수 있습니다.
6. Python 풀이에서는 실행할 `Solution` 구현을 선택하고 **테스트 실행**을 누릅니다.
7. **파일 맨 끝에 빈줄 추가하기**를 누르면 모든 내 제출의 파일 끝 줄바꿈을 검사하고 수정합니다.
8. 아직 풀지 않은 문제 카드를 누르고 생성 경로를 확인합니다.
9. 풀이 파일을 지우려면 **삭제**를 누른 뒤 두 확인창에서 계속 진행합니다.

라인린트 일괄 수정은 `end-of-file` 규칙에 따라 비어 있지 않은 파일이 정확히 하나의 `\n`으로 끝나도록 합니다. 파일 끝에 스페이스 또는 탭으로만 이루어진 줄이나 여러 빈 줄이 이어져 있으면 모두 하나의 끝 줄바꿈으로 정리하며, `*.md` 제출은 제외합니다.

생성 대상과 이름이 같은 파일은 덮어쓰지 않습니다. 대소문자만 다른 파일이 이미 있어 충돌할 수 있는 경우에도 생성을 중단합니다. 제한 모드에서는 목록 조회만 지원하며 파일 생성에는 워크스페이스 신뢰가 필요합니다.

풀이 파일의 푸시 상태는 현재 브랜치의 upstream을 기준으로 판정합니다. 미커밋 변경,
스테이징된 변경 또는 아직 upstream으로 푸시하지 않은 커밋에 포함된 파일은
`미푸시`로 표시합니다. Git 저장소가 아니거나 현재 브랜치에 upstream이 없으면
`푸시 상태 확인 불가`로 표시합니다.

문제 본문은 **현재 문제 보기**를 처음 선택할 때 LeetCode의 비공식 GraphQL API로
불러오며 확장을 다시 시작하기 전까지 캐시합니다. API가 변경되거나 네트워크가
연결되지 않은 경우에는 사이드바에서 다시 시도하거나 LeetCode 문제 페이지를 직접
열 수 있습니다. Premium 문제의 비공개 본문은 표시되지 않습니다.

### 로컬 Python 풀이 테스트

테스트 러너는 저장 여부와 관계없이 현재 에디터에 보이는 Python 코드를 사용합니다.
한 파일에 같은 이름의 `Solution` 클래스나 대상 메서드가 여러 번 있어도 줄 번호로
구분해 원하는 구현을 선택할 수 있습니다. `typing`, `array`, `bisect`,
`collections`, `functools`, `itertools`, `heapq`, `math` 등 일반적인 LeetCode
Python 환경의 라이브러리는 러너가 먼저 import합니다.

`ListNode`, `TreeNode`, `Node`, `NestedInteger`처럼 문제에 따라 구조가 달라지는
객체는 러너가 선언하지 않습니다. 현재 풀이 또는 테스트에서 실제로 필요한 객체가
파일에 선언되거나 import되지 않았다면 필요한 이름을 안내하고 실행을 중단합니다.
객체가 필요 없는 문제에는 이 검사가 적용되지 않습니다.

테스트는
[`newfacade/LeetCodeDataset`](https://huggingface.co/datasets/newfacade/LeetCodeDataset)의
고정 리비전 `215604aeed660029df7de2fea5a4d7b6ed476a08`에서 현재 스터디 문제에
해당하는 Python 검증 코드만 추출한 것입니다. 75문제 중 68문제를 지원하며,
데이터가 없는 7문제는 사이드바에 별도로 표시됩니다. 이 결과는 제3자 데이터셋에
대한 로컬 실행 결과이며 LeetCode의 공식 실행 또는 제출 결과가 아닙니다.

실행은 신뢰된 워크스페이스에서만 가능하고 10초 후 종료되며 출력은 1MB로
제한됩니다. 별도의 OS 보안 샌드박스가 아니므로 신뢰하는 코드만 실행해야 합니다.
기본 실행기는 `python3`이며 설정에서 다른 경로나 실행 파일로 바꿀 수 있습니다.

## 로컬 개발

Node.js `24.18.0`을 사용합니다.

```sh
nvm use
yarn install
yarn compile
```

VS Code의 실행 및 디버그에서 다음 구성을 사용할 수 있습니다.

- `leetcode-study에서 확장 실행`: 형제 경로 `../leetcode-study`를 대상으로 실행
- `테스트 데이터에서 확장 실행`: 저장소에 포함된 작은 테스트 데이터를 대상으로 실행

주요 명령:

```sh
yarn lint
yarn typecheck
yarn test:unit
yarn test:integration
yarn test
yarn dataset:sync
```

통합 테스트는 `.tmp`에 격리된 멀티 루트 워크스페이스를 만든 뒤 `@vscode/test-electron`으로 VS Code 확장 개발 호스트에서 실행됩니다.

## VSIX 만들기

```sh
yarn package:vsix
```

모든 검사와 테스트가 성공하면 `.artifacts/leetcode-study-helper.vsix`가 생성됩니다. VS Code의 **Extensions: Install from VSIX...** 명령으로 설치할 수 있습니다.

## 저장소 감지 규칙

- 워크스페이스 루트에 유효한 `problem-categories.json`이 있어야 합니다.
- JSON 키와 이름이 같은 최상위 문제 폴더가 하나 이상 있어야 합니다.
- 제출 파일은 문제 폴더 바로 아래에서만 찾습니다.
- `README.md`와 하위 폴더의 파일은 제출로 처리하지 않습니다.

## 설정

- `leetcodeStudyHelper.nickname`: 제출 파일에서 찾을 닉네임
- `leetcodeStudyHelper.preferredLanguage`: 새 파일을 만들 때 사용할 언어와 확장자
- `leetcodeStudyHelper.pythonExecutable`: Python 테스트에 사용할 실행 파일 또는 절대 경로

두 설정은 전역으로 저장되어 다른 LeetCode Study 워크스페이스에서도 동일하게 사용됩니다.
